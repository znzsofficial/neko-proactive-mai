# Neko Proactive Mai

MaiBot 主动聊天调度插件，插件 ID 为 `neko.proactive`。

## 2.8.0 · 简单时间输入与基础周期并行

新建模型计划统一北京时间，模型不再填写timezone/IANA/UTC偏移；旧计划的绝对时刻、时区、锚点和unknown原样保留，不在加载或读页时迁移。工具只暴露下面列出的参数，旧代码调用的时区/首次时刻字段仅保内部兼容，不进入模型Schema。

- 单次：`neko_proactive_wake(action, at?, intent?)`，at可填`10分钟后`、`2小时后`、`21:30`、`明天09:00`或`2026-11-02 09:00`，未来1分钟～7天。HH:MM只指今天，已过时刻报错，不猜成明天。
- 重复：`neko_proactive_repeat(action, interval_minutes?, local_time?, intent?)`。`interval_minutes=120`代表每2小时；`local_time="21:00"`代表每天北京时间21点，两者不能同时填。省去kind和首次at，已有计划可只改intent；暂停状态不因编辑恢复。
- 日程：`neko_proactive_dayplan(action, at?, intent?, item_id?, version?)`。**只能安排今天**，at只填北京时间HH:MM，至少1分钟后，不能填写明天/以后；最多6项，建议2～4，可留空。修改/取消须get返回的ID和版本；旧已保存非北京时间日程仍按旧时区保留额度，新的简单时间同时须属于北京时间今天和旧日程当天，不靠时区重置额度。

**单次/重复不再接管或关闭基础唤醒。** 原周期照常检查，只有同目标计划已到点/未来60秒内、60秒持久安全间距或已有提交在途时短暂避让。基础检查不消费/修改任何计划；私聊基础提交前复用原last_dispatch先持久化60秒防重，释放原锁再Host RPC，失败/取消/unknown也不立即重投；不新增调度器、锁或状态格式。单次相对其他显式计划的优先、日程合并、重启不补播保持。

管理页去除可编辑时区，日程只选今天几点；新单次/重复使用北京时间，编辑旧单次/重复时继续展示并沿用其原时区。页面不再显示“基础暂停/接管”，只显示基础实际deadline及临近避让。

## 2.6.1 · 计划独立与Planner请求观测（沿用边界）

**明确的单次/重复计划不套用基础周期规则。** `start_time/end_time/check_interval/jitter/probability/min_interval_between_chats/isolation_time`只管默认基础唤醒；5分钟计划不因基础冷却、夜间或真人活跃推迟。共用总暂停、当前授权/真实session、持久60秒安全间距和串行提交；基础周期与计划并行（旧接管已在2.8.0移除），重启错过不补播，计划提交不改基础成功冷却时间。

修复计划提交跨Host RPC持有预约锁、并行Planner Hook等待同一锁的时序风险：先持久unknown/下一轮，再释放锁调用Host，以in-flight标记串行；Hook可按真实session、不透明wake ID和Host任务号绑定尚未回执的unknown记录，临时意图只注入一次。回执后重新读索引，仅更新对应occurrence，不覆盖Hook的shown/请求观测或其他目标管理写入。正在提交的同目标修改会明确拒绝；取消/崩溃仍保留unknown，不自动重放。

页面区分“Host已入队，尚未观测到Planner请求”与“Planner请求已到达插件Hook”；后者只证明请求前Hook经过，不证明模型完成、发言或QQ送达。旧shown=true但无观测时刻只显示旧提示已提供，不补造实际开始/未回复记录。Host enqueue会投递内部proactive队列并恢复WAIT，消费者仍可能等待当前运行轮结束；入队不是同步执行或闹钟保证。

2.6.0下文中计划沿用基础时段/最小间隔/静默的规则已由本节取代；原基础周期自身数值和规则不变。标准发布器现已由父仓支持本插件根webui.html安全白名单，本版继续仅用标准更新入口，不手工上传。

## 2.6.0 · 单次与重复联系节奏

新增当前授权私聊的固定间隔/每日重复计划，沿用唯一调度器。管理页改为宿主支持的隔离custom扩展：真实聊天导航、单次与重复分区、日期时间/时区表单、按目标和真实会话隔离的草稿、预填/放弃草稿、中文操作结果与CAS冲突恢复。没有立即唤醒、试发、未知重放或另一套全局配置保存器。

标准维护发布器已支持本插件根`webui.html`安全资产的精确SHA/哈希验证与上传白名单；不得使用旧的排除HTML选集、手工SFTP或运行时生成HTML。本仓源码包烟测包含并检查HTML。宿主支持custom协议2即可，不修改宿主、不新增服务端口/CDN/页面独立认证。

### 模型工具（实际主描述可见）

- `neko_proactive_wake(action="get"|"set"|"cancel", at?, intent?)`管理当前私聊唯一单次预约，使用上节简单北京时间；intent为1～240字依据，set替换旧单次，get返回真实时刻和状态。
- `neko_proactive_repeat(action="get"|"set"|"pause"|"resume"|"delete", interval_minutes?, local_time?, intent?)`管理唯一重复计划。interval_minutes为1～10080整数分钟，或local_time为每天北京时间HH:MM；修改已有计划可省略沿用字段，只改意图不移动锚点。修改暂停计划不自动恢复，resume才继续。
- 两个工具没有目标参数，只消费Host可信当前私聊上下文、当前名单及新鲜session。主说明写在SDK实际采用的`brief_description`/`description`链，不只放宿主不读取的detailed字段；deferred/tool_search与已发现工具Schema使用同一可见描述。内容仅说明“稍后具体话题用单次、持续联系用重复、可沉默、不必每次设、不保证提醒”，不加常驻system prompt、不改Planner/Replyer模板、宿主人设、群私意图。

### 调度与每轮持久边界

基础周期独立运行，不因保存单次或启用重复而暂停。显式计划之间保留单次优先、临近日程合并/同窗重复避让；基础仅临近已到/60秒内计划或安全间距/在途提交时让行。群聊原周期、原参数/名单/意图保持，明确计划不受基础时段/冷却/静默/概率制约。

interval保留稳定绝对锚点，不按刷新/模型耗时重新计时。新daily用北京时间HH:MM；旧daily继续用已存时区，DST缺失跳当天、重叠仅较早一次。页面编辑旧计划沿用原时区，禁止重写旧绝对时间来“迁移”。

每个重复计划只保留未来当前轮、最近尝试结果/任务关联及最近跳过原因，不积压历史。到点只复核总暂停、当前授权和每目标/全局≥60秒安全间距；安全阻挡每分钟检查，不调用模型，最多等到下一标称轮或24小时（先到为准）后跳过到严格未来。单次接管期间错过的重复不补播。重启错过当前轮也跳到未来；未来轮跨重启保留。暂停/继续、删除、改期不清60秒attempt guard。

每轮**Host I/O前**将该occurrence持久unknown/attempt，并将下一轮推进到未来；明确接收/拒绝/未知都不重放本轮。unknown在崩溃/取消/最终写失败时保留；下一轮仍受原最小间隔而不是立即重试。接收仅Host入队，不证明QQ送达。具体意图只通过原任务ID/真实session匹配的临时Planner Item展示一次，后续请求/Replyer/摘要仍清理。删除计划保留必要的最近不明归因与防重时间，不召回已接受任务。

### 存储与回滚

旧`private-wakes.json` v1单次可原样读取，不因页面读操作迁移。首次保存重复时原子写v2，保留原slots/unknown/last_dispatch，再增加有界repeats；仍最多128目标、256KiB、0600/fsync/原子替换，损坏/未知格式保原拒绝。未写重复仍保持v1，无新数据库/worker/全局发送账本；普通周期冷却仍内存。

**v2不能直接退回≤2.5.1。旧版会拒绝版本2并加载失败，而不会悄悄忽略重复计划恢复默认私聊周期。** 回滚须先保全v2/unknown/配置，明确退役重复计划并另行审核离线兼容转换与防重时间；不能只把version改1或用旧快照覆盖。即使已删除全部重复，文件仍v2，避免隐式降级。需要即时回滚时保留现场、选择匹配版本/维护窗口，由管理员决定，不自动清状态。未做存储降级/生产回滚演练。

### 管理页

入口仍`/extensions/neko.proactive/manage`。页面只通过Host注入的`maibot.query/action`及声明绑定通信：Host登录cookie/owner/静态private API、确认、CAS、参数白名单和并发预算继续生效；页面sandbox禁止网络/同源/表单提交/worker，HTML只含内联样式/脚本，没有token/私钥或直接HTTP路径。所有聊天名称/短意图用textContent，不执行HTML。

`wake_overview/wake_save/wake_cancel`旧private API保留；新增private `wake_edit`供页面单次/重复操作，中文业务错误明确返回`success=false`给页面显示，不冒充操作成功。target/session只能从当前Host名单交集选择，模型工具不借管理员权限。停用时仍可查看、取消/暂停/删除，拒绝新增/恢复；撤权和session改变不露旧私聊意图。

页面每15秒低频只读刷新，编辑中暂停；手动刷新保草稿，按目标＋真实session隔离，变更后仍携带旧CAS拒绝覆盖，可“放弃草稿，载入最新”。异步请求busy/generation阻止晚到覆盖和重复操作，确认由Host桥提供。真实deadline只来自唯一循环，浏览器只格式化，不推算下一执行；基础规则仍从原插件配置页设置。静默仅显示原调度器观测，不为页面查询私聊历史。

## 与 v1.x 的区别

**v2.0.0 是一个彻底的重构。**

旧版（v1.x）自行构建 prompt → 直接调 LLM → 自己发消息，绕过了 Maisaka 的整个人格/记忆/表达系统。麦麦主动说话时跟被动回复时的性格不一样——等于两个人在用同一个号。

新版把"找话题"的意图注入 Planner 上下文，由 Maisaka 全权处理：
- 使用和被动回复**相同的人格和记忆**
- 自行判断是否应该回复、回复什么、怎么表达
- 不再需要单独配置 LLM 模型、prompt 模板、表达风格

## 安装

将本项目目录放到 MaiBot 的 `plugins/` 下并在 WebUI 启用。插件 ID 为 `neko.proactive`，首次迁移时由维护脚本迁移配置和Life能力文件。支持源码和配置热加载，不需要重启麦麦。

## 配置

```toml
[plugin]
enabled = false
config_version = "2.0.0"
version = "2.6.1"

[scheduler]
enabled = true
start_time = "08:00"        # 每日开始时间
end_time = "23:00"          # 每日结束时间
check_interval = 30          # 检查间隔（分钟）
jitter = 3                   # 间隔波动（分钟）
probability = 0.7            # 触发概率 0~1
min_interval_between_chats = 60  # 两次主动最小间隔（分钟）
isolation_time = 0           # 距上次真人消息至少静默分钟数

[target]
allowed_groups = []          # 白名单群号
allowed_friends = ["12345678"]  # 白名单QQ号

[log]
verbose = true
scheduler_log = true

[intent]
group_text = "结合当前对话、记忆和可用素材自然聊两句，没有合适内容可以不发" # 自定义简例，不预设冷场
private_text = "优先分享有依据的见闻或想法，不补写具体日常；可续聊、问早，叫起床须有真实约定" # 自定义简例，完整默认见config.py/随仓库模板
reason = "attention_proactive"         # 触发原因标识
```

在WebUI的intent设置里分别填写group_text和private_text；旧text已删除，不再读取或回退。源码发布仍不覆盖线上配置，更新现有私聊提示需保存private_text；清理旧字段可通过配置原始TOML编辑器删除intent下的text。

## 使用

插件按调度周期自动检查，满足条件时通过 `maisaka.proactive.trigger()` 注入意图。

手动触发：在已注册的会话中发送 `/saymai`。

### 调度参数的边界

- `check_interval`是一轮检查完成后的等待分钟数，`jitter`对等待随机加减分钟，不是生成正文后延迟发送；如45±5，通常等40～50分钟。启动后可立即检查，最短等待1分钟。
- `probability`是每个目标符合时段/冷却/静默条件后的提交概率，不是QQ发送概率；`min_interval_between_chats`从本插件上次自动任务被宿主接受起算，不按QQ投递或其他插件发言计时。冷却仅内存，完整重载/重启不保证续接。
- `isolation_time=0`表示不要求真人静默，不证明群里冷场。活动时段按服务器进程本地时间，支持跨午夜，开始结束相同不是全天。
- 所有上述条件只管本插件自动检查，不是其他插件的全局限流/白名单。B站只提供候选，因此仍受这里的自动条件及B站侧日额度/间隔共同约束；别的插件直接唤醒/发送另走自己的规则。
- `/saymai`仍检查总开关/目标授权，但不走自动时段、概率、静默/冷却，也不更新自动冷却；这是原有手动语义，不作正常验收探针。
- `log.scheduler_log`控制调度/跳过日志；`verbose`兼容保留但当前没有实际读取，不影响频率。没有新增模型审核或配置校验行为。

### 私聊自主预约

工具`neko_proactive_wake(action, at?, intent?)`：

- `action="get"`查看当前会话的一条预约及终态；`"set"`设置或替换，`"cancel"`取消尚未提交的预约。没有好友、群或session参数；额外的这些字段不参与授权。群聊不能使用，当前插件/调度开关、好友白名单、宿主真实私聊及当前会话解析共同决定授权。
- `at`按北京时间填写`10分钟后`、`21:30`、`明天09:00`或日期时间；未来60秒至7天，intent为1～240字依据。新进展不自动取消安排，Planner使用最新上下文，仍可取消/替换过时安排。
- 无预约时，原群聊/私聊周期、抖动、概率完全保留；有待执行预约时，仅抑制同一私聊的普通周期。预约不抽概率，但**不绕过**服务器本地活动时段、原最小间隔、真人静默期和授权。预约时区只解释绝对时刻，不改服务器活动时段。
- 到点被时段/冷却/静默阻挡，保存`blocked`及原因，每分钟重新检查规则，不调用模型；最长阻挡24小时后`expired`。每轮最多提交一条预约，预约提交至少相隔60秒，不批量补播。普通周期不因预约唤醒而提前检查其他会话；现有`/saymai`手动语义不变，不作为预约或验收探针。
- `private-wakes.json`保存在插件`data_dir`，跨正常重载/重启保留未来预约。**重载/重启时已经到期的预约一律标记`expired/restart_missed`，不补执行**。配置热更新保留未来/已阻挡预约；关闭插件/调度器时不提交，卸载取消唯一调度任务。撤权或真实会话改变则将旧预约标`revoked`，不移交到新会话。
- Host调用前将该预约持久标为`unknown`；返回明确接收记`submitted`，明确拒绝记`rejected`，异常/取消/崩溃窗口仍`unknown`。三者都不会自动重放该预约，`submitted`只是宿主接收，不是模型已发言或QQ送达。终态后可自主设置新预约，但每次尝试都保留至少原最小间隔/60秒的持久防重间隔，重约、取消、重启不清除；普通周期仍遵守这个预约防重间隔。
- 仅预约尝试的防重时间新增持久化，**普通周期原成功冷却仍仅内存**，未重写其他发送账本。文件上限256KiB/128个目标槽，每目标一条（含终态）；满额拒绝新增目标，仍可替换已有槽，不自动淘汰未知记录。损坏、超限、未知版本或软链接索引保留并拒绝读写，不覆盖为空。该文件含简短意图，应按其他插件数据管理，源码包不包含它。
- 任务历史仅携带不透明预约ID及原私聊配置意图；预约具体意图只在180秒内匹配真实任务/会话后注入一次Planner临时Item，下一次请求、Replyer及维护fork摘要入口清理，不修改历史/已有摘要。缺失/未知任务关联或已撤权时不补注入，不拿预约状态当发送成功证明。普通群聊B站素材链、停用Life、原配置均不改变。

### 主动唤醒管理页

- WebUI侧栏「主动唤醒管理」，或`/extensions/neko.proactive/manage`。使用宿主协议2声明式表格、行详情、表单、确认和错误提示，不运行独立Web服务、不新增监听端口。基础参数入口仍是「插件管理 → Neko Proactive Mai → 配置」。
- 基础deadline来自唯一调度器，不由浏览器估算；基础与单次/重复/日程并行，不显示全程接管，临近计划或安全间距仅短暂避让。静默只展示上次检查观测，读页不查历史。
- 私聊表只列最新名单与真实会话交集。新单次填写北京时间日期/时间和意图，日程只填今天几点；旧时区不提供可编辑入口但保留原时间。CAS、改意图不移动旧时刻、unknown不重放保持。
- 管理保存/取消与模型工具共用业务校验、WakeStore和原锁；管理保存带行版本校验，模型、调度器、其他页面或重复请求改变该预约后，旧页面操作拒绝，刷新重选。保存/取消只通知已有scheduler event，不改变其他目标基础deadline；没有「立即执行/试发/重放」按钮。
- 总开关或调度关闭时仍可查看；Runner仍加载时可以取消当前授权私聊的pending预约，不能新建/替换。卸载后API随Runner下线。撤权/旧会话记录只展示必要状态，不展示旧意图；页面读取不擅自将其改为revoked、不更新shown、不触发调度或模型。实际调度继续按2.4.0边界复核授权。
- 页面使用手动刷新。宿主声明式轮询每次会失效行选择并关闭详情，故不在编辑期间轮询；原生busy/请求取消保护阻止重复提交和晚到响应覆盖。操作失败显示宿主错误横幅；点击刷新可看「最近管理操作」的中文详细诊断（宿主原生组件不展示自定义API异常正文），不会以成功返回值掩盖失败。原生表单草稿会在当前页面保留，切换目标前核对字段；保存确认冻结所选目标与参数。
- 预约原状态文件兼容新增可选`last_outcome`，只保留该目标最近一次预约尝试的接收/拒绝/未知结果，改期保留；提交前先落`unknown`，仍无自动重放。旧2.4.0缺字段时只展示能确认的原状态，不推测此前结果。普通周期最近结果和静默观测仍仅内存、有界，不增加全局发送账本；旧版代码也能读取该可选字段，不需状态迁移。
- 页目标投影最多128项、观测/最近结果各256项，超过明确标注；Host查询与锁等待有7秒上限，失败是真实错误，不返回空白成功。索引损坏/超限继续保留且拒绝操作。

## 手动触发

# 行为边界

## 一、改动过大

v2.0.0 删掉了 v1.x 的整套 prompt 构建、LLM 调用、消息格式化逻辑。如果你是从旧版升级，配置文件的 `[topic]`、`[llm]`、`[message]`、`[persona]`、`[prompt]` 节全部作废，需要删除或忽略。不删除也不会报错（toml 允许未知节），但不会再有任何效果。

## 二、与 Maisaka 行为绑定

v2.0.0 不再控制"说什么"，只控制"什么时候触发"。Maisaka 收到 intent 后可能：
- 回复一个话题（你想要的）
- 回一句"嗯"然后沉默
- 完全不理你（它觉得不需要说话）
- 调用其他工具（如果它觉得有必要）

这些行为本插件不控制。如果麦麦不说话，那是 Maisaka 的决定，不是插件坏了。

## 三、功能性免责

- 所有目标流注册在内存中，插件重载后重新查询 stream_id
- `isolation_time` 依赖 `message.get_by_time_in_chat` 查询历史消息，极端情况下可能查不到最新消息
- 全局配置 `bot.qq_account` 未设置时无法过滤 bot 自己的消息，隔离期可能被自己触发打断
- 白名单为空时不生效——这是设计，不是 bug

## 四、宇宙级免责

本插件按「AS IS」提供。作者不对以下后果负责，包括但不限于：
- 麦麦在群里突然开始聊奇怪的话题
- 麦麦因为 Maisaka 觉得"不想说话"而一直沉默
- 麦麦在凌晨三点因为时区配置错误触发了
- 群友发现麦麦的性格比原来活泼/高冷了一倍
- 猫踩键盘修改了 intent 文本

使用即接受。不接受就别开 `scheduler.enabled`。

### 保留的 v1.x 特性说明（仅作历史记录）

- **话题来源**：`history` / `knowledge` / `preset` / `mixed` 四种模式

- **消息格式**：`[message]` 节控制时间前缀

| 功能 | v1.x | v2.0.0 |
|------|------|--------|

| 意图控制 | 复杂的 prompt 模板系统 | 单条 intent 文本 |
| 配置体积 | ~30 个配置项 | ~15 个配置项 |
